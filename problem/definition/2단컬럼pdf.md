## 📌 문제 정의 (Problem Definition)

### 1. 문제 배경

본 프로젝트에서는 학술 PDF 문서를 텍스트로 추출한 뒤, 이를 청크 단위로 분할하여 임베딩하고 벡터 DB(Qdrant 등)에 저장하여 RAG 기반 질의응답을 수행한다.

그러나 다수의 학술 논문 PDF는 좌·우 2단 컬럼 구조를 사용하고 있으며, 일반적인 PDF 텍스트 추출 방식은 이러한 레이아웃 구조를 고려하지 않는다.

### 2. 문제 현상

2단 컬럼 PDF를 단순 텍스트 추출(extract_text()) 방식으로 처리할 경우, 다음과 같은 문제가 발생한다.

동일한 y좌표 상에 위치한
좌측 컬럼의 문장과 우측 컬럼의 문장이 하나의 문장처럼 병합됨

그 결과, 의미적으로 무관한 문장이 하나의 청크에 섞여 임베딩됨

예시
Um YJ, Oh SW, Lee CM, Kwon HT, Joh HK, Kim YJ, Kim HJ, Ahn SH. 
Dietary fat intake and the risk of metabolic syndrome in Korean adults.
양소를 중심으로 한국인의 영양소 섭취 상태 및 특성을 기술하고 있다.


위와 같이

좌측 컬럼의 영문 참고문헌

우측 컬럼의 국문 Peer Review Commentary

가 하나의 문장으로 인식되는 현상이 발생한다.

### 3. 문제의 영향

이 문제는 단순한 텍스트 가독성 문제를 넘어, RAG 시스템 전반의 성능 저하로 직결된다.

## 🔴 주요 영향

임베딩 품질 저하

하나의 벡터에 서로 다른 주제·언어·문맥이 혼합됨

코사인 유사도 기반 검색 정확도 급격히 하락

검색 결과 신뢰도 하락

질문과 무관한 문단이 상위 검색 결과로 노출

LLM 응답의 환각(hallucination) 가능성 증가

청크 단위 의미 붕괴

청크가 더 이상 “의미 단위”가 아님

Chunk size / overlap 튜닝으로 해결 불가

### 4. 근본 원인 분석 (Root Cause)

PDF는 문단 기반 포맷이 아니라 좌표(x, y) 기반 그래픽 포맷

대부분의 PDF 파서는

텍스트를 y좌표 기준으로 정렬

동일한 y라인에 있는 텍스트를 좌 → 우로 단순 연결

2단 컬럼 구조에 대한 레이아웃 인식 로직 부재

👉 즉, 문제의 본질은 청크 분할 문제가 아니라 레이아웃 처리 문제이다.

## 🛠 해결 방안 (Solution)
### 1. 해결 전략 개요

임베딩 이전 단계에서 반드시 PDF 레이아웃(컬럼)을 분리한 뒤 텍스트를 추출한다

이를 위해, 텍스트 추출 파이프라인을 다음과 같이 재설계한다.

[기존]
PDF → extract_text → chunk → embedding

[개선]
PDF → layout-aware extraction → column/section 분리
    → semantic chunking → embedding

### 2. 해결 방안 ① 컬럼 분리 기반 텍스트 추출 (권장 ⭐⭐⭐⭐⭐)
🔹 접근 방식

PDF 페이지를 좌측 컬럼 / 우측 컬럼 영역으로 분할

각 컬럼을 독립적으로 텍스트 추출

논문 읽기 흐름에 맞게 좌 → 우 순서로 결합

🔹 기대 효과

좌·우 컬럼 문장 혼합 문제 완전 해결

참고문헌, 본문, 해설 영역 분리 가능

이후 청크 분할 시 의미 단위 유지
